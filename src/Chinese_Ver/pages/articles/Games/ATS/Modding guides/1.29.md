# Games/ATS/模组制作指南/1.29

## 建议

- 以原始模型为基础制作模型时，请在你的模组中也加入它所使用的**所有**原始 /automat/ 文件。文件名是根据其内容生成的 CityHash64 哈希，因此每当我们以任何方式更改材质参数时，都会使用另一个文件来存储它们，而如果没有其他模型使用原始参数，原始文件可能不再存在。
- 修改原始模型时，务必包含模型的**所有**组件（pmg+pmd），而不只是你更改过的部分。否则，如果我们更改了模型，你可能会遇到崩溃。
- 一如既往，向支持多文件方式（例如 road_look.sii）的文件添加新对象时，**强烈建议**在名称中使用后缀或前缀，以避免与我们在补丁中新增的对象冲突。否则，当新补丁发布时，你可能不得不使用批量重命名功能（参见批量重命名）来修复冲突。

## 如何转换地图

- 加载地图
- 如果由于某些模板（例如道路外观 us_tmpl5）被移除而导致加载失败，请从先前版本中复制相应的定义。
- 尝试保存。保存可能会因复合对象之间的冲突而失败。此时，请在不退出游戏的情况下检查游戏日志（以便轻松重复保存操作）。如果日志中包含复合对象错误，可以按以下方式修复：
  - **“Compound X contains item Y which also exists as independent one”** - 使用 g_delete_uid Y 控制台命令删除该项。
  - **“Duplicate item X found in compounds:”** - 使用查找对话框找到复合对象中的相应项，并将其移除（通过项属性）。这会把情况转变为前一种情形，即复合对象与独立项冲突。
- 执行重建（F8）
- 保存地图
- 从“Map\Validate road shoulders”运行路肩检查。这会生成所有可能对随机事件造成问题的项列表（主要是模型穿模）。你有以下选项：
  - 通过移动或删除这些项来调整它们，使其不再引发问题
  - 将相关道路标记为路肩受阻（道路项属性中的“Shoulder blocked”复选框），以阻止生成事件。
  - 如果你不在意这些问题，可以忽略该项。
- 保存地图

## 变更

### 新的导航数据

新的导航算法会使用来自交通车道的详细信息，因此可以考虑车道数量、方向及其他因素。请注意确保地图中的导航数据正确。例如，如果十字路口预制件没有用于右转的 AI 车道，导航就不会右转，即使这意味着它会找到一条长得多的路径。

***/def/map_data.sii*** 中的 ***map_data*** 单元包含若干属性，可用于调整路径规划启发式和预估行驶时间。

导航使用的通用值：

- ***navigation_maximum_speed*** (25.0) - 用于导航计算的最大合理速度（单位 m/s）。保持较小值可提高搜索效率。
- ***navigation_turn_back_length*** (400000.0) - 用于表示 AI 线路所不允许的掉头的人工连接的长度。
- ***navigation_prefer_small_wide_road_penalty*** (10.0) - 使用 prefer_small_roads 路径模式时，施加于任一方向车道数超过一条的道路的惩罚值。乘法叠加。
- ***navigation_special_prefab_additive_penalty*** (0.0) - 施加于经过城市外特殊预制件（例如加油站）的路径的惩罚值，单位为米。加法叠加。通常应保持为零，除非地图中使用的加油/称重站预制件都不包含加油站区域之外的普通道路。
- ***navigation_special_prefab_additive_penalty_city*** (0.0) - 施加于经过城市内特殊预制件（例如加油站）的路径的惩罚值，单位为米。加法叠加。通常应保持为零，参见 ***navigation_special_prefab_additive_penalty***。
- ***navigation_gps_avoid_additive_penalty*** (20000.0) - 施加于经过标记为“GPS Avoid”的道路或预制件的路径的惩罚值，单位为米。加法叠加。

在 ***prefer_shorter*** 路径模式下用于寻路的权重。

- ***navigation_city_penalty*** (1.0) - 施加于穿过城市区域的路径的惩罚值。乘法叠加
- ***navigation_slow_road_penalty*** (5.0) - 施加于穿过慢速时段区域的路径的惩罚值。乘法叠加

在 ***best*** 路径模式下用于寻路的权重：

- ***navigation_narrow_road_max_speed_usage*** (0.8) - 在窄路上使用的最高速度比例。
- ***navigation_road_max_speed_usage*** (0.9) - 在普通道路上使用的最高速度比例。
- ***navigation_city_or_slowtime_speed_penalty*** (0.25) - 在城市或慢速时段区域行驶时施加于速度的惩罚值。乘法叠加。
- ***navigation_semaphore_wait_duration*** (90.0) - 通过信号灯的时间成本，以游戏时间秒为单位。
- ***navigation_stop_wait_duration*** (60.0) - 通过停车标志的时间成本，以游戏时间秒为单位。
- ***navigation_turn_own_side_duration*** (15.0) - 向本侧转向（例如在美国/欧洲大陆为右转，在英国为左转）的时间成本。加法叠加。
- ***navigation_turn_oposite_side_duration*** (45.0) - 向对侧转向（例如在美国/欧洲大陆为左转，在英国为右转）的时间成本。加法叠加。

用于时间估算的权重：

- ***navigation_time_narrow_road_max_speed_usage*** (0.8) - 在窄路上使用的最高速度比例 - 时间计算。
- ***navigation_time_road_max_speed_usage*** (0.9) - 在普通道路上使用的最高速度比例 - 时间计算。
- ***navigation_time_city_or_slowtime_speed_penalty*** (0.85) - 在城市或慢速时段区域行驶时施加于速度的惩罚值 - 时间计算。乘法叠加。
- ***navigation_time_semaphore_wait_duration*** (60.0) - 通过信号灯的时间成本，以游戏时间秒为单位 - 时间计算。
- ***navigation_time_stop_wait_duration*** (30.0f) - 通过停车标志的时间成本，以游戏时间秒为单位 - 时间计算。
- ***navigation_time_turn_own_side_duration*** (10.0f) - 向本侧转向（例如在美国/欧洲大陆为右转，在英国为左转）的时间成本 - 时间计算。加法叠加。
- ***navigation_time_turn_oposite_side_duration*** (30.0) - 向对侧转向（例如在美国/欧洲大陆为左转，在英国为右转）的时间成本 - 时间计算。加法叠加。

编辑器中的道路项可以标记“GPS Avoid”标志。这会使导航对使用该道路的路径施加大幅惩罚。预制件项没有这样的标志，但 prefab_model 定义支持 gps_avoid 属性，可为地图中该预制件的所有使用位置启用它。

### 预制件

预制件格式已更改，加入了供新导航使用的独立数据。对于 AI 线路格式正确的旧预制件，游戏应能自动转换，而新版本的 Conversion Tools 也会自动生成这些数据。

#### 格式变更

新格式新增了导航节点。它们同时由普通预制件节点和 AI 曲线派生而来。每个导航节点对应普通节点或 AI 曲线的端点。基本上，它是 AI 曲线之上的一幅简化图，用于表示对导航重要的位置（例如 AI 车道的端点），以减小导航图的规模。

导航节点表的存储方式与其他表相同。该表的偏移量和大小紧跟在交叉口表的对应字段之后存储。

每个导航节点具有以下格式

```
u8 type; // Type of node. 0 = physical node, 1 = AI curve
u16 index; // Depending on the type it is either index of normal node or index of AI curve to whose ending point this nav node corresponds
u8 connection_count; // Number of outgoing connections leading to other navigational nodes (0-4)
connection_info connections[4]; // Information about those connections. First connection_count entries are used. Rest is set to {0xffff, MAX_FLOAT, 0, 0xffff[8]}
```

每条连接信息的结构具有以下格式

```
u16 target_node; // Index of navigational node this connection leads to
float length; // Length of the connection in meters
u8 curve_count; // Number of AI curves the connection is created from, limited to 8, if more would be necessary, insert additional nav node
u16 curve_indices[8]; // Indices of the relevant AI curves in order they should be used. First curve_count entries are used, reset is set to 0xffff.
```

此外，AI 曲线结构也已更改，在其末尾添加了一个 u32 值。该值包含当导航从该 AI 曲线开始时应当使用的导航节点索引，如果没有则为 0xffffffff。基本上，它是对节点中 curve_indices 的反向映射。

### 光晕数据

flare blink 单元（通常是 ***/unit/hookup*** 目录中以挂接方式定义的模型）已重做，改用闪烁模式，而不再只是简单的 ON 和 OFF 延迟。因此，***blink_delay_on*** 和 ***blink_delay_off*** 属性已被移除，并替换为 ***blink_pattern*** 和 ***blink_step_length***。该单元现在的定义如下：

```
SiiNunit
{
flare_blink : flare.model.my_blink
{
	dir_type: wide

	blink_pattern: "X--"     # String of X and - characters, where X represents ON state and - represents OFF state.
	blink_step_length: 0.5   # Float representing duration of one step inside blink pattern in seconds.

	model: "/model/flare/my_flare.pmd"
}
}
```

因此，flare blink sync 从 flare blink 单元继承了属性和行为，并具有相同的两个新属性：***blink_pattern*** 和 ***blink_step_length***。

### 时区数据

时区（目前）以国家为基础。每个国家都定义了 ***time_zone***（整数，单位为分钟）和 ***time_zone_name***（字符串）。例如，太平洋夏令时为 -420 分钟，名称为“PDT”。

此外还有一个默认时区，存储在 ***economy_data*** 单元中（***default_time_zone***、***default_time_zone_name***），这是预期游戏基准时间所在的时区，在相关空间位置（因而时区）未知时都会使用它。

### 经济数据

一些旧值已被导出为 ***economy_data*** 单元（***/def/economy_data.sii***）的属性：

- ***tow_price_base*** (150.0)
- ***tow_price_factor*** (0.4)
- ***tow_time_base*** (1800.0)
- ***tow_time_factor*** (3.0)
- ***tow_fuel_ratio*** (0.3)
- ***truck_scales_cost*** (10)

### 交通

交通相关数据有几处变更。由于其性质，其中一些**未提供向后兼容性**，因此请检查你的模组是否存在潜在问题。如果相应定义未被修改，你应该不会有任何问题。

#### 交通车道数据

所有交通车道属性（定义于：***/def/world/traffic_lane.sii***）现在都通过一组交通规则（参见 #Traffic rules）来定义，而不再为某些功能设置专用属性。这样便可将各种“功能”（例如道路标线、车辆类型通行权限、车辆生成……）组合到交通车道中，而无需专用属性。

> **注意：** 交通车道没有定义“默认交通规则”。每种车道类型都必须手动定义所有需要的属性。

*示例：具有地方道路速度等级、多种车辆类型的生成规则以及“允许超车”规则的车道：*

```
traffic_lane_data : traffic_lane.road.local
{
   speed_class: local_road
   traffic_rules[]: traffic_rule.road      # Allow access for road vehicles
   traffic_rules[]: traffic_rule.s_car_l
   traffic_rules[]: traffic_rule.s_truck_l
   traffic_rules[]: traffic_rule.s_bus_l
   traffic_rules[]: traffic_rule.s_police
   traffic_rules[]: traffic_rule.overtake_alw   # Allow overtaking (including 'wrong way')
}
```

*示例：仅允许卡车生成或进入的交通车道：*

```
traffic_lane_data : traffic_lane.road.freeway.truck_lane
{
   speed_class: freeway
   traffic_rules[]: traffic_rule.s_truck_h
   traffic_rules[]: traffic_rule.trucks_only
}
```

*示例：没有任何规则的交通车道（即不生成车辆，也不允许车辆进入）：*

```
traffic_lane_data : traffic_lane.no_vehicles
{
   speed_class: local_road
}
```

#### 道路外观中的交通车道数据

所有道路外观中与交通相关的属性都通过交通车道定义（参见 #Traffic lane data）。要为各种道路模板变体定义不同的车道配置，可以使用 ***template_variants_left*** 和 ***template_variants_right*** 属性。

*示例：1+1 车道道路的道路外观。只有部分模板变体（道路标线为虚线或无标线）允许超车：*

```
road_look : road.template0 {
   name:          "ca 1x1 country small border tmpl"
   template_right:      "/road_template/ca_nv/ca_1x1_small_border.pmd"

   lanes_left[]:   traffic_lane.road.local.no_overtake
   lanes_right[]:   traffic_lane.road.local.no_overtake

   template_variants_right[]: .tmpl_var.road.template0

   compatible_edges_right[]: "shldr_1m"
   compatible_edges_right[]: "shldr_05m"
   compatible_edges_right[]: "shldr_1m2"
   compatible_edges_right[]: "sw_kerb"
   compatible_edges_right[]: "sw_4m_a"
   compatible_edges_right[]: "sw_4m_c"

   shoulder_space_left:      1.0
   shoulder_space_right:      1.0

}
road_template_variant : .tmpl_var.road.template0
{
   variant_names[]: "no_lines"
   variant_names[]: "lines_broken"

   lanes_left[]:   traffic_lane.road.local
   lanes_right[]:   traffic_lane.road.local
}
```

*示例：高速公路道路外观，包含一个“卡车车道”变体和一个在最外侧车道禁止变道的变体：*

```
road_look : road.us_tmpl13 {
	name: 			"us 0-3 freeway tmpl"
	template_right:		"/road_template/us/us_3_freeway_one_way.pmd"

	lanes_right[]:	traffic_lane.road.freeway
	lanes_right[]:	traffic_lane.road.freeway
	lanes_right[]:	traffic_lane.road.freeway
	template_variants_right[]: .tmpl_var.road.us_tmpl13
	template_variants_right[]: .tmpl_var2.road.us_tmpl13
	compatible_edges_right[]: "sh"
	shoulder_space_right:		3.0
}
road_template_variant : .tmpl_var.road.us_tmpl13
{
	variant_names[]: "truck_lane"
	lanes_right[]:	traffic_lane.road.freeway
	lanes_right[]:	traffic_lane.road.freeway
	lanes_right[]:	traffic_lane.road.freeway.truck_lane
}
road_template_variant : .tmpl_var2.road.us_tmpl13
{
	variant_names[]: "brd_brk_ful"
	lanes_right[]:	traffic_lane.road.freeway
	lanes_right[]:	traffic_lane.road.freeway.full_out
	lanes_right[]:	traffic_lane.road.freeway.full_in
}
```

#### 交通规则

##### 优先级修改器

优先级修改器交通规则（***rule: "priority"***）的第三个参数已更改。旧定义将无法正常工作，因为未提供向后兼容性。

*示例：两种最常见的优先级规则：*

```
traffic_rule_data : traffic_rule.major_road
{
	name: "Priority road"
	rule: "priority"
	num_params[]: -1	# no prirority value change
	num_params[]: 0		# not additive
	num_params[]: 2		# type 'priority_road'
}
traffic_rule_data : traffic_rule.minor_road
{
	rule: "priority"
	num_params[]: -1 	# no prirority value change
	num_params[]: 0		# not additive
	num_params[]: 1		# type 'give_way'
}
```

##### 生成密度

生成密度的定义方式已完全重新设计。旧定义将无法正常工作，因为未提供向后兼容性。

现在不再定义生成系数，而是可以为每种车辆类型分别定义一天中的交通密度变化。为提高可读性，所有与密度相关的规则都已添加到 ***traffic_rules_spawn.sui***，并由 ***traffic_rules.sii*** 包含。

> **注意：** 当同时通过交通车道（参见 #Traffic lane data）和交通区域项为同一车辆类型应用交通密度规则时，***交通区域规则会覆盖车道规则***。

*示例：轿车生成密度变化（“低密度”版本）：*

```
traffic_rule_data : traffic_rule.s_car_l
{
	# name: "Spawn density car low"
	rule: "density"
	str_params[]: "car"
	num_params[]: 7.0	# 7:00
	num_params[]: 0.15	# frequency
	num_params[]: 10	# count limit
	num_params[]: 17.0	# 17:00
	num_params[]: 0.1	# frequency
	num_params[]: 10	# count limit
	num_params[]: 0.0	# 00:00
	num_params[]: 0.05	# frequency
	num_params[]: 3		# count limit
}
```

*示例：火车生成密度（恒定）：*

```
traffic_rule_data : traffic_rule.s_train_c
{
	# name: "Spawn density cargo train"
	rule: "density"
	str_params[]: "train_cargo"
	num_params[]: 0.0	# 00:00
	num_params[]: 0.03	# frequency
	num_params[]: 2		# count limit
}
```
