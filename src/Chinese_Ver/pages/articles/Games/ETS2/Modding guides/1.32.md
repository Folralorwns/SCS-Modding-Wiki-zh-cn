# 游戏/ETS2/模组指南/1.32

## 简介

本页面包含针对游戏新更新版本的模组制作指南。

为了更好地理解单元的变化，建议查阅[单元文档](../../../Documentation/Engine/Units.md)页面。

## 建议

- 当你以原始模型为基础制作自己的模型时，也请在模组中加入该模型所使用的**所有**原始 /automat/ 文件。这些文件的名称是根据其内容生成的 CityHash64 哈希值，因此每当我们以任何方式更改材质参数时，都会改用另一个文件来存储它们，而如果没有其他模型使用原始参数，原始文件可能就会消失。
- 修改原始模型时，请务必包含该模型的**所有**组件（pmg+pmd），而不仅仅是你修改过的组件。否则一旦我们更改了模型，你的模组就可能崩溃。
- 一如既往，在向支持多文件方式的文件（例如 road_look.sii）中添加新对象时，**强烈建议**在名称中使用后缀或前缀，以避免与我们在补丁中新增的对象发生冲突。否则当新补丁发布时，你可能需要使用批量重命名功能（参见批量重命名）来解决冲突。

## 如何转换地图

- 对于所有 **dynamic** 设为 true 的标志牌，将参数 **instanced** 设为 true。需要这样做的模型会通过 "Non instanced dynamic road model is not supported! (sign)" 错误消息报告。
- 如果你的模组定义直接引用了云杉植被模型（位于 **/model/vegetation/poly_vegetation/**），则需要更新这些定义以引用新版本。
- 加载地图
- 执行重建（F8）
- 保存地图
- 对于 look 选项发生变化的模型，选择正确的 look

## 更改

### 地图格式更改

信号灯配置档可以在预制件项层级被覆盖。

### UI 纹理更改

我们将 UI 纹理的混合改为 gamma 正确的方式。因此，UI 纹理中的 alpha 过渡（例如配件图标、自定义加载界面）以及 UI 界面定义中指定的 alpha 值，都会产生与之前不同的结果。创建透明纹理时，应将图形编辑器配置为使用 Gamma 值 1.0，以使合成效果与游戏中的行为一致。

虽然目前没有完全自动化的方式可以修改纹理以获得与之前完全相同的结果，但[附带的 Perl 脚本](http://download.eurotrucksimulator2.com/tga_adjust_for_gamma_1.zip)可用于调整 alpha 通道，从而在假定混合基于下述表达式且在中灰色背景上完成的情况下保持外观相似。请注意，使用该脚本后，你可能仍需要手动调整图像以获得你想要的外观。

```
S .. source sRGB color in UI texture
a .. source alpha in UI texture
D .. background sRGB color, we assume middle gray #808080
b .. recomputed alpha

The old blending expression:

OLD = S * a + D * (1 - a)

The new blending expression:

NEW = sRGB(rgb(S) * b + rgb(D) * (1 - b))

Alpha which would result in the same final value after blend:

b = (rgb(OLD) - rgb(D)) / (rgb(S) - rgb(D))
```

### 经济系统更改

整个货物生成器自先前版本以来发生了巨大变化：

1. 货物现在按单位而非单纯的重量来定义。一个单位的货物占据一定容积，由此可确定可装入挂车车身的单位数量。质量与报酬也由该单位数量推导而来。质量还会受到挂车本身或国家法规的进一步限制。两者都可能导致所装载的货物单位数量减少。
2. 另一个新概念是车身类型：挂车与货物不再直接关联，而是通过车身类型进行匹配。车身类型为 **flatbed** 的挂车只会生成由与 **flatbed** 车身兼容的货物构成的任务。

#### 货物数据

属性 **price_coef**（float）、**mass**（float 数组，每辆挂车）和 **cog_height_offset**（float 数组，每辆挂车）已被移除。属性数组 **trailers** 仅为部分货物的兼容性而保留。

新属性：

- [token array] **body_types** - 货物可装载的挂车车身列表。
- [float] **volume** - 单个单位的容积，单位为立方米（m3）
- [float] **mass** - 一个货物单位的质量，单位为千克（kg）
- [float] **unit_reward_per_km** - 每 1km 距离运输一个货物单位的报酬
- [float] **unit_load_time** - 一个货物单位的装载时间，单位为秒
- [bool] **overweight** - 带有此标志的货物会正常使用，但会忽略任何挂车或国家限制。

#### 挂车 def

结构 **trailer_def** 经过大幅改进与重新设计，成为经济的核心。针对给定货物列出挂车的旧系统仅用于其余旧式挂车（在货物文件夹中放置定义，填充 **trailer** 链接，并使用带下划线的伪挂车 **body_type**）。

此外，使用新的自购挂车系统的挂车 def 现在放置于 **/def/vehicle/trailer_defs** 文件夹中。而旧系统的挂车 def 仍保留在其原始位置。

新字段支持仅通过带有附加信息的挂车车身类型将货物与挂车匹配的系统。最重要的有：

- [float] **gross_trailer_weight_limit** - 挂车与货物质量的技术或逻辑限值，还会受到桥梁公式或类似规则的限制。
- [token] **body_type** - 定义可装载的货物，应等于组合中所有挂车车身的 body_type
- [token array] **country_validity** - 允许该挂车通行的国家列表，空列表表示不施加任何限制

此外还有缓存/预计算值，用于快速访问而无需加载所有配件（取代沿链条累加所有底盘与车身质量的做法），以及针对未定义全部配件的挂车（例如货运市场挂车）的数据：

- [float] **trailer_mass** - 所有挂车底盘部件的质量总和
- [float] **body_mass** - 所有挂车车身部件的质量总和
- [float] **volume** - 所有挂车车身部件的容积总和
- [int] **axles** - 组合中所有挂车的车轴总数
- [float] **length** - 整个挂车组合的长度，单位为米
- [token] **chain_type** - 挂车组合链的类型（single、double、b_double 等）

此外，还有重心放置参数——与旧机制不同，现在它就是普通的货物重心偏移，单位为米（此前出于历史原因，高度会被减半）。

##### 车身类型

车身类型定义挂车可以运输哪些货物，并通过货物数据中新的数组属性 **body_types** 与货物定义绑定到经济系统。

有若干预定义类型在代码中具有特殊处理：

- **flatbed**
- **curtainside**
- **dryvan**
- **insulated**
- **refrigerated**

话虽如此，仍可为车身类型使用自定义 token，但不要忘记为其定义新的货物数据。不过，在未来的更新中，预定义列表很可能会随着新的车身类型集合而扩充。

### 经济数据

- 新增 **cargo_damage_cost** 属性，定义玩家每 1% 损伤需支付多少费用。
- 新增 **cargo_damage_cost_factor** 属性，定义每 1% 损伤所乘的损伤惩罚系数。
- 新增 **exp_park_load_bonus** 属性，定义玩家在任务装载期间停放挂车所获得的经验奖励大小。
- 新增 **revenue_per_km_base** 属性，定义 AI 司机的每公里基础收入（必须与常规货物运费成比例）。
- 新增 **revenue_coef_per_km** 属性，定义货运市场与在线任务的每公里薪资系数。
- 新增 **cargo_market_revenue_coef_per_km** 属性，定义货物市场任务的每公里薪资系数。
- 新增 **driver_revenue_coef_per_km** 属性，定义 AI 司机和玩家快速任务的薪资系数。
- 新增 **driver_cargo_market_revenue_coef_per_km** 属性，定义 AI 司机货物市场任务的薪资系数。

- 移除 **revenue_per_km**。
- 移除 **driver_revenue_per_km**。
- 移除 **trailer_damage_cost**。
- 移除 **trailer_damage_cost_factor**。
- 移除 **brands**，游戏现在会在启动时从 `/def/vehicle/truck_dealer` 和 `/def/vehicle/trailer_dealer` 目录收集卡车与挂车品牌。其中每个可被解释为 token 的目录都是一个新品牌。

### 游戏数据

- 新增 **blinker_auto_off_trigger** 属性，用于定义此前转向灯自动关闭所依据的角度下限。

### 国家数据

国家数据新增了一个名为 **mass_limit_per_axle_count** 的属性。它定义 GVW（车辆总质量）——在该国境内，具有给定车轴数量（卡车与挂车总数）的整个车辆组合（卡车 + 挂车 + 货物）所允许的最大质量限值（单位为千克，kg）。空数组表示不施加任何限制。

第一个元素描述 2 轴车辆的质量限值，第二个描述 3 轴车辆，依此类推。如果车辆的车轴数超过已定义项，则使用最后一项作为限值。

```
country_data: country.data.uk
{
	# [...]

	mass_limit_per_axle_count[]: 18000	# 2-axle vehicle
	mass_limit_per_axle_count[]: 26000      # 3-axle vehicle
	mass_limit_per_axle_count[]: 38000      # 4-axle vehicle
	mass_limit_per_axle_count[]: 40000      # 5-axle vehicle
	mass_limit_per_axle_count[]: 44000      # 6 and more-axle vehicle
}
```

### 光晕数据

光晕单元（通常以 hookup 定义的模型形式出现在 **/unit/hookup** 目录中）新增了手动定义光晕缩放曲线的功能，并带有两个新的 float 属性：

- **scaling_start_distance** - 定义光晕缩放开始的距离。
- **scaling_end_distance** - 定义光晕缩放结束的距离，此时光晕缩放达到 **scale_factor**。

请注意，这两个属性都以米为单位保存距离，并且除非 **scale_factor** 大于 1.0，否则不会使用它们。

### 车辆数据

#### 挂车线缆数据

现在支持直式挂车线缆，可通过新的 float 属性 **straight_cable_length** 启用：当使用该属性且其值大于零时，会将螺旋线缆转换为直式线缆，并告知游戏直式线缆的实际距离。

此外，现在还支持线缆几何体中所谓的 "back faces"（背面），可通过将布尔属性 **back_faces** 设为 true 来启用。当在线缆上使用透明材质时，这会很有用，这样线缆内壁也会可见（例如，新的 AI 交通车辆挂车线缆目前就使用了背面）。

#### 卡车数据

##### 配件前照灯数据

标志牌照明算法已更改，从现在起，标志牌的照明将基于常规卡车灯光的颜色和范围计算。

以下属性已废弃，不再使用：

- **low_beam_sign_(color/range)**
- **hi_beam_sign_(color/range)**
- **front_beam_sign_(color/range)**
- **roof_beam_sign_(color/range)**
- **front_roof_beam_sign_(color/range)**

#### 挂车数据

挂车数据中新增了若干内容，并在 **/def/vehicle** 内加入了新的文件夹结构：

1. **trailer_cargo** - 用于定义货物模型与挂车车身匹配关系的容器文件夹。
2. **trailer_chain_types** - 用于定义游戏中所有挂车可能使用的挂车组合链类型的文件夹。
3. **trailer_dealer** - 挂车经销商的报价，按 <brand.model> 子文件夹分类。
4. **trailer_defs** - 新系统中所有可能的挂车组合的配置（参见 #Cargo generator）。
5. **trailer_owned** - 自购挂车数据，定义配置、车身、涂装和配件（与卡车类似），按 <brand.model> 子文件夹分类。

此外，用于定义货运市场挂车的 **trailer** 单元新增了指针属性 **trailer_definition**，可通过指向新类型的 **trailer_def** 将该货运市场挂车关联到经济系统。

##### 挂车经销商数据

挂车经销商报价的定义方式与卡车经销商报价完全相同。

在 **/def/vehicle/trailer_dealer/** 文件夹中，每个挂车品牌都有对应的文件夹，其中包含玩家可在游戏内选择的各种预设报价的完整定义。

##### 配件挂车数据

新单元（**/def/vehicle/trailer_owned/<brand.model>/data.sii**）用于描述挂车的品牌和系列。它与广为人知的 **accessory_truck_data** 非常相似。

该单元的属性如下：

- [string] **info[0]** - （可选）品牌名称；如果传入空字符串，则不显示品牌。
- [string] **info[1]** - （可选）挂车系列名称。
- [string array] **fallback** - （可选）回退配件列表，格式为 **type|path**
- 给定车辆的其他常规规则和要求

##### 配件挂车车身数据

在 **/def/vehicle/trailer_owned/<brand.model>/body/** 文件夹中定义挂车车身的新配件类型。

必需属性：

- [float] **volume** - 车身容积，单位为 m3。限制可装载的货物单位数量。
- [token] **body_type** - 车身类型。只有具有给定 body_type 的货物才能装载。
- [float] **mass** - 空车身的质量，单位为 kg。如果所有质量都存储在底盘中，则可为 0。
- [float3] **total_size** - 挂车的总尺寸，单位为米（当前未使用）。
- [float3] **size** - 挂车车身的内部尺寸，单位为米，显示在提示框中。

可选属性：

- [string] **detail_model** - 车身的详细模型。
- [string] **model** - 车身的默认模型。
- [string array] **lods** - LOD 模型。
- [string] **collision** - 车身的碰撞。
- [token] **variant** - 要使用的模型 variant。
- [token] **look** - 要使用的模型 look。

##### 自购挂车配置

每辆自购挂车都需要自己的配置，玩家可在挂车配置器中选择（例如单节 3 轴、单节 2 轴、双节、b-double）。所有配置组合都定义在 **/def/vehicle/trailer_owned/<brand.model>/configurations** 中。

类型为 **trailer_configuration** 的每个挂车配置具有以下属性：

- [string] **name** - 该配置在挂车配置器中显示的名称。
- [string] **icon** - 该配置在挂车配置器中显示的图标。
- [token] **chain_type** - 该配置使用的组合链类型（**/def/vehicle/trailer_chain_types/** 中定义的组合链类型之一。
- [string array] **chassis** - 该配置的所有底盘定义，第一个底盘对应组合链中的第一辆挂车，第二个底盘对应第二辆挂车，依此类推。
- [trailer_body_set array] **body_sets** - 与此配置兼容的 **trailer_body_set** 的所有者指针数组。除了配置文件中手动链接的车身组之外，它们还会从名称与基础配置文件名相同的子文件夹中收集（文件名取到第一个点为止，因此配置 "*single3.sii*" 或 "*single3.mymod.sii*" 的车身组应放在 "*/def/vehicle/trailer_owned/<brand.model>/configurations/single3*" 文件夹中）。

###### 挂车车身组

挂车车身组定义可用于单个挂车配置的车身集合。每个车身组随后都可由玩家在挂车配置器中选择。

每个挂车车身组包含：

- [string] **name** - 该配置在挂车配置器中显示的名称。
- [string] **icon** - 该配置在挂车配置器中显示的图标。
- [trailer_def pointer] **trailer_definition** - 指向该挂车车身组所使用的挂车定义的指针，游戏通过它了解该挂车配置与车身组可以使用哪种货物。
- [string array] **body** - 该车身组的所有车身定义，第一个车身对应组合链中的第一辆挂车，第二个车身对应第二辆挂车，依此类推。
