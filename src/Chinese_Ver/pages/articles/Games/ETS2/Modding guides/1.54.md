# 游戏/ETS2/模组指南/1.54

## 简介

本页包含游戏新版本的模组制作指南。

为更好地理解单元方面的更改，建议查阅[单元文档](../../../Documentation/Engine/Units.md)页面。

## 建议

- 当你以原始模型为基础制作模型时，请在模组中一并加入该模型所使用的**全部**原始 /automat/ 文件。文件名称由其内容的 CityHash64 哈希生成，因此无论我们以何种方式修改材质参数，都会改用另一个文件来存储这些参数，如果没有其他模型使用原始参数，原文件就可能不再存在。
- 修改原始模型时，请始终包含模型的**全部**组件（pmg+pmd），而不只是你改动过的那些。否则一旦我们更改该模型，就可能引发崩溃。
- 一如既往，在向支持多文件方式（例如 road_look.sii）的文件添加新对象时，**强烈建议**在名称中使用后缀或前缀，以避免与我们在补丁中新增的对象发生冲突。否则当新补丁发布时，你可能不得不使用批量重命名功能（参见批量重命名）来修复冲突。

## 更改与新增功能

### 货物系统

新的货物系统旨在将挂车及其货物模型解耦为通用装配体，使采用特定装载方式的挂车能够自动装载任何使用该方式的货物。该系统旨在将挂车数据与货物数据相互独立地定义。

基本上，通过货物模型匹配将货物绑定到挂车的方式保持不变。变化的是这两者的绑定方式。例如，如果你正在制作一辆应支持游戏中现有货物的新挂车，只需为车身定义正确的 ***cargo_loading_methods*** 以及车身中的其余辅助数据即可，无需扩展货物数据。

同样，如果你想添加新货物，在大多数情况下无需改动任何挂车数据。只要定义了新的货物模型匹配，一切就应正常工作；例外是 ***custom*** 装载方式，此时你需要按车身、按货物定义自定义装载数据。仅当你的特殊货物无法使用其他任何装载方式时，才应使用这种装载方式。

总而言之，你需要做什么取决于你是在向游戏中添加新挂车还是新货物：

- 对于新挂车：通过 **accessory_trailer_body_data_u** 设置挂车数据，并确保你的挂车使用车身配件且已链接 **trailer_def_u** 单元。对于自购挂车，该单元链接在 **trailer_body_set_u** 单元内部；对于货运市场挂车，则链接在 `/def/vehicle/trailer/<trailer>.sui` 中定义的主 **trailer_u** 内部
- 对于新货物：像以往一样定义 **cargo_data_u**，并将新增的货物模型匹配及其所属货物配件放入文件夹：`/def/vehicle/cargo/<cargo_name>/`。

#### 挂车数据

为支持挂车上的货物装载与捆扎，必须使用车身配件，这是强制要求，因为货物系统会从其中加载新的属性：

- **cargo_loading_methods[]** - token 数组，表示该车身支持的货物[装载方式|#Loading-Methods]
- **cargo_regular_width** - 浮点数，表示挂车的加宽部件在何种宽度下开启
- **cargo_warning_signs** - 布尔值，表示车身是否支持警告标志部件的切换
- **cargo_areas** - 区域尺寸 (X,Z) 数组，用于任何基于区域的装载方式
- **cargo_areas_cylinder_data[]** - 与货物区域一一对应的数组，存储基于圆柱体的装载所需附加数据（每项表示给定货物区域的高度与坡度角）
- **cargo_custom_loads[]** - **cargo_custom_load_data_u** 单元指针数组，存储每种货物的自定义装载偏移
- **cargo_lashing_mounts[]** - **cargo_lashing_mount_u** 单元指针数组，存储捆扎座定义
- **cargo_lashing_strap** - 指向 **cargo_lashing_gear_u** 的单元指针，存储货物模型匹配选择 strap 装置方式时所使用的捆扎装置配置
- **cargo_lashing_chain** - 指向 **cargo_lashing_gear_u** 的单元指针，存储货物模型匹配选择 chain 装置方式时所使用的捆扎装置配置。

如果车身设置了 ***cargo_warning_signs: true***，游戏将根据所装载货物模型的包围盒，尝试切换车身、底盘以及所选配件模型上的特定部件，规则如下：

- 若所装载货物的宽度小于 2.5m，将开启 **wrn_sgn_off** 部件
- 若所装载货物的宽度大于 2.5m 且小于 2.9m，将开启 **wrn_sgn_29** 部件
- 若所装载货物的宽度大于 2.9m 且小于 3.2m，将开启 **wrn_sgn_32** 部件
- 若所装载货物的宽度大于 3.2m，将开启 **wrn_sgn_max** 部件

此外，如果所装载货物的宽度大于车身数据中设置的 ***cargo_regular_width***，则挂车车身或底盘（如果不存在挂车车身模型）上的加宽部件将被开启。加宽部件的收集方式随装载方式而异：

- 对于基于 ***area*** 的装载方式，游戏会查找 `larea_on_X` 和 `larea_off_X` 部件，其中 `X` 是 ***cargo_areas[]*** 属性中区域的索引。
- 对于其余装载方式，游戏会查找 `cargo_on` 和 `cargo_off` 部件。

两种情况下，游戏都会确保禁用不属于当前所用装载方式的任何部件。使用 ***area*** 装载时，`cargo_on` 和 `cargo_off` 都会被禁用；反之，使用非基于区域的装载方式时，任何 `larea_on_X` 和 `larea_off_X` 都会被禁用。

##### 货物自定义装载数据

新增了单元 **cargo_custom_load_data_u**，用于存储货物模型匹配的自定义装载位置：

- **cargo_token** - 使用此自定义装载数据的货物后缀 token
- **offset** - 相对于货物定位器的位置偏移
- **rotation** - 相对于货物定位器的旋转偏移，单位为度

##### 货物捆扎座

新增了单元 **cargo_lashing_mount_u**，用于在车身上捆扎货物，并定义开启/闭合的环模型：

- **spacing** - 浮点数，定义捆扎座上各个捆扎点之间的间距
- **hook_angle_constraints** - float3，定义与此捆扎座配合使用的挂钩在各轴上的角度约束，范围为 0 至 90°（0 表示不允许旋转，90° 表示可向负方向或正方向旋转 90 度）
- **open_model** - 字符串，指向在捆扎座上进行捆扎时所放置模型的路径
- **closed_model** - 字符串，指向未使用间隔位置时在捆扎座上所放置模型的路径（仅当 spacing 大于 0 时才会放置此模型）

为使捆扎座正确加载，车身或底盘（如果未定义车身模型）必须具有正确的模型定位器对：`lashm_s_X` 和 `lashm_e_X`，其中 `X` 是挂车车身数据的 ***cargo_lashing_mounts*** 数组中捆扎座的索引。第一个定位器表示捆扎座的起点，第二个表示终点。请注意，捆扎座应沿车辆前进轴从车辆前部向后部依次放置。

##### 货物捆扎装置

新增了单元 **cargo_lashing_gear_u**，用于存储捆扎装置数据：

- **material** - 字符串，引用用于表现所生成捆扎几何体外观的材质
- **size** - float2，定义所生成捆扎几何体相交部分的宽度与高度
- **texcoord_uratio** - 浮点数，定义所生成几何体的材质中所用纹理的 U 比例：uratio = texture_width / texture_height
- **start_hook** - 字符串，指向在生成的捆扎路径起点处添加的模型的路径
- **start_hook_length** - 浮点数，表示从模型原点到挂钩沿其前进方向的末端的长度，捆扎将按此长度偏移
- **end_hook** - 字符串，指向在生成的捆扎路径终点处添加的模型的路径
- **end_hook_length** - 浮点数，表示从模型原点到挂钩沿其前进方向的末端的长度，捆扎将按此长度偏移
- **binder** - 字符串，指向插入捆扎第一段的张紧器模型的路径，模型必须沿前进方向放置，才能与生成的捆扎正确对齐
- **binder_length** - 浮点数，表示从模型原点到张紧器底部沿其反向前进方向的末端的长度

#### 货物模型匹配数据

货物模型匹配单元已移入车辆定义空间，因为它们只能与车辆和货物装载逻辑配合使用。此外，现有的货物模型匹配单元已重构，现支持以下属性：

- **data_path[]** - 字符串数组，定义同一货物模型匹配的不同模型（即尺寸相同但外观不同）
- **dimensions** - float3，表示货物模型匹配在各轴（X,Y,Z）上的尺寸。Y 分量目前被忽略，但将来可能会使用。
- **unit_volume_factor** - 浮点数，作为货物数据中定义的货物单位容积的系数。通常用于区分同一货物的不同货物模型匹配，这些模型外观完全不同，因而与货物单位容积的比例也不同。除非你要为现有货物定义新的货物模型匹配，或拥有多个货物模型匹配，否则不应定义该属性
- **loading_method** - 货物模型匹配将使用的装载方式的 token，参见 #Cargo loading methods
- **lashing_method** - 货物模型匹配将使用的捆扎方式的 token，参见 #Cargo lashing methods
- **lashing_gear_type** - 货物模型匹配将使用的捆扎装置的 token，参见 #Cargo lashing gear types
- **lashing_hook_angle_constraints** - float3，定义挂钩在各轴上的角度约束，范围为 0 至 90°（其工作方式与车身捆扎座上的角度约束类似，区别在于它仅在该货物模型匹配使用 `direct` 捆扎时生效）

#### 通用结构

通用结构会直接或间接地用于双方。

##### 货物装载方式

如上所述，货物装载方式会告知货物与挂车，特定的货物模型匹配将如何装载到挂车上。游戏会针对每种装载方式采用不同的装载实现：

- **area** - 货物放置在区域上，游戏会自动计算能装入挂车的货物模型匹配数量
- **area_cont_20ft** - 用于 20ft 集装箱的 ***area*** 变体
- **area_cont_40ft** - 用于 40ft 集装箱的 ***area*** 变体
- **area_cont_45ft** - 用于 45ft 集装箱的 ***area*** 变体
- **area_cont_53ft** - 用于 53ft 集装箱的 ***area*** 变体
- **area_cylinder** - 圆柱形货物，放置在由底部区域和顶部区域定义的棱柱体积中
- **area_logger** - 用于带侧向支撑的运木车的 ***area*** 变体
- **auxiliary_only** - 没有实际货物，仅在自定义节点上放置辅助模型（例如 ADR、冷藏车灯）
- **bulk** - 散装货物，通过生成网格进行装载
- **custom** - 货物按照货物定位器以及车身内定义的 ***cargo_custom_load_data_u'*** 进行自定义放置

所有基于区域的装载方式都会在车身或底盘（如果不存在车身模型）中查找 `larea_s_X` 和 `larea_e_X` 模型定位器，其中 `X` 是挂车车身数据 ***cargo_areas[]*** 属性中装载区域的索引。这些定位器定义每个装载区域平面的角点。

##### 货物捆扎方式

捆扎方式定义货物如何被捆扎到挂车上：

- **direct** - 货物通过其上的刚性点直接捆扎到挂车捆扎座
- **top_over** - 采用顶部越过技术捆扎货物，尝试在装载区域上找到垂直的捆扎路径
- **none** - 货物不进行捆扎，可与固定在挂车上或自身已捆扎的货物配合使用

每种方式（***none*** 除外）都需要货物模型中不同的定位器。

对于 ***direct*** 捆扎，货物模型需要按以下方式命名的定位器：`lash_d_X`，其中 `X` 是从 0 到 99 的递增索引。一旦找不到给定索引的模型定位器，其余索引都将被忽略。捆扎将沿模型定位器的前进轴方向进行，游戏会从车辆上选择尽可能最近的捆扎座位置。

对于 ***top_over*** 捆扎，货物模型需要按以下方式命名的捆扎轨道定位器：`lash_s_Z_X` 和 `lash_e_Z_X`，其中 `Z` 表示沿模型前进轴的多条轨道的索引，`X` 表示沿模型 X 轴的多条轨道的索引。当模型中存在遮挡、需要手动划分为多条轨道时（例如某些分隔构件），通常会使用多条轨道。在所有其他情况下，应使用单一 Z 轨道索引，因为游戏会以 1.25m 的间距放置多条捆扎。X 索引应从左到右进行（在模型空间中从 -X 到 +X）

##### 货物捆扎装置类型

目前有两种不同的捆扎装置类型：

- **chain** - 游戏生成菱形交叉段，并结合 alpha 测试材质来模拟链条网
- **strap** - 游戏生成方形交叉段来模拟绑带网
- **none** - 游戏不使用任何捆扎，应与 ***none*** 捆扎方式配合使用

#### 交通挂车数据

交通车辆也进行了重做。与玩家车辆类似，它们现在需要链接 **trailer_def_u**，并通过新属性 **cargoes[]** 提供其支持的货物列表，该属性是货物名称 token 的数组。因此，如果你想创建新的交通挂车，需要：

1. 从 `/def/vehicle/trailer_defs/` 链接永久挂车定义
2. 为其添加车身配件
3. 提供支持的货物数组。

交通挂车定义示例：

```
traffic_trailer : traffic.trailer.scs_brick_r
{
	trailer_definition: trailer_def.scs.flatbed.single_3.brick

	accessories[]: .scs_brick_r.chassis
	accessories[]: .scs_brick_r.rwheel
	accessories[]: .scs_brick_r.rwheel2
	accessories[]: .scs_brick_r.rwheel3
	accessories[]: .scs_brick_r.body
	accessories[]: .scs_brick_r.paint_job

	cargo_mass: 20000

	tags[]: low
	tags[]: flatbed
	tags[]: brick
	tags[]: medium
	tags[]: cargo
	tags[]: construct

	cargoes[]: fertilizer
	cargoes[]: bricks
	cargoes[]: outdr_flr_tl
	cargoes[]: plant_substr
}

vehicle_accessory: .scs_brick_r.chassis
{
	data_path: "/def/vehicle/trailer/scs_brick/red.sii"
}

vehicle_wheel_accessory: .scs_brick_r.rwheel
{
	offset: 0
	data_path: "/def/vehicle/t_wheel/single_385_55_steel.sii"
}

vehicle_wheel_accessory: .scs_brick_r.rwheel2
{
	offset: 2
	data_path: "/def/vehicle/t_wheel/single_385_55_steel.sii"
}

vehicle_wheel_accessory: .scs_brick_r.rwheel3
{
	offset: 4
	data_path: "/def/vehicle/t_wheel/single_385_55_steel.sii"
}
vehicle_accessory: .scs_brick_r.body
{
	data_path: "/def/vehicle/trailer/scs_brick/accessory/body.sii"
}
vehicle_paint_job_accessory: .scs_brick_r.paint_job
{
	data_path: "/def/vehicle/trailer/scs_brick/custom_paint_job/red.sii"

```
