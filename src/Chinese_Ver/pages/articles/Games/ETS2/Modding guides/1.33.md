# 游戏/ETS2/模组指南/1.33

## 简介

本页面包含针对游戏新更新的模组制作指南。

为了更好地理解单元方面的改动，建议查阅[单元文档](../../../Documentation/Engine/Units.md)页面。

## 建议

- 当你以原始模型为基础制作自己的模型时，也请在模组中加入该模型所使用的**所有**原始 /automat/ 文件。这些文件的名称是根据其内容计算出的 CityHash64 哈希值，因此每当我们以任何方式更改材质参数时，都会改用另一个文件来存储它们，而如果没有其他模型使用原始参数，原始文件可能就不再存在。
- 修改原始模型时，请务必包含该模型的**所有**组件（pmg+pmd），而不仅仅是你改动过的组件。否则一旦我们更改模型，你的模组就可能崩溃。
- 一如既往，在向支持多文件方式的文件（例如 road_look.sii）中添加新对象时，**强烈建议**在名称中使用后缀或前缀，以避免与我们在补丁中新增的对象发生冲突。否则当新补丁出现时，你可能需要使用批量重命名功能（参见批量重命名）来解决冲突。

## 如何转换地图

- 如果你的模组添加了爱沙尼亚、拉脱维亚、立陶宛、俄罗斯或芬兰，请更新你的国家、渡轮、信号灯模型和信号灯配置档定义，以避免冲突。
- 加载地图
- 执行重建（F8）
- 保存地图
- 对于外观选择发生变化的模型，选择正确的外观

## 更改与新功能

### 云档案

本次更新支持使用 Steam 云，可按每个驾驶员档案分别启用。请注意，云仅用于存储档案数据和存档。如果你使用云在多台计算机之间同步档案，仍需确保这些档案所需的模组在所有相关计算机上都可用且为最新版本，可以借助 Steam 创意工坊或手动完成。

如果档案未启用云功能（这是现有档案的默认行为），它将像以前一样存储在 **"[游戏用户路径](../../../Documentation/Engine/Game%20user%20path.md)/profiles"** 中。如果档案启用了云功能，其大部分文件由 Steam 客户端在内部管理。但仍有小部分档案配置不存储在云上，其中包含与硬件相关的设置，例如输入绑定或声音设置。这部分存储在 **"[游戏用户路径](../../../Documentation/Engine/Game%20user%20path.md)/steam_profiles"**" 中，你需要在每台使用该云档案的新计算机上配置这部分。

与未启用云的档案一样，游戏会在新版本首次于该计算机上运行时创建档案的备份副本。请注意，备份副本以本地副本的形式创建。如果你想从中恢复某些内容，需要先在 Steam 中为该档案关闭云功能，从备份中复制文件，然后再重新启用。

### 单元命名更改

现在对 sii 文件中单元名称的解析更加严格。以前会忽略名称末尾的点（例如 “vehicle.something.”），并把多个连续的点当作一个（例如 “vehicle..something”）。从 1.33 起，这两种名称均无效，将无法加载。此外，名称中以点分隔的各部分总数现在限制为 10。

### 预制件更改

新增 “Long Trailer” 生成点类型。在该点上不会执行针对 **allowed_trailer_length** 的检查。如果公司预制件包含至少一个长挂车点，游戏经济系统还会将不限长度的挂车送达该预制件（简单点）。

### 城市数据

为名称本地化功能新增了 **city_name_localized** 和 **short_city_name_localized** 属性。如果未显式定义，则默认为最接近的逻辑变体（短名称使用非短名称，本地化名称使用非本地化名称）。**city_name_uppercase** 属性已被移除，该字符串现在由游戏根据相应的本地化或非本地化名称生成。

### 国家数据

为名称本地化功能新增了 **name_localized**。其用法与之前的原始名称相同。原来的 **name** 现在包含未翻译的名称（与城市的情况类似）。如果未显式定义 **name_localized**，则默认为 **name**。

### 渡轮数据

为名称本地化功能新增了 **ferry_name_localized**。如果未显式定义，则默认为 **ferry_name**。

### 游戏数据

- 属性 **glass_config** 已废弃，因为驾驶室内玻璃配置现在位于单独的文件中：**/def/vehicle/interior_glass_config.sii**。

### 驾驶室内玻璃配置

关于玻璃窗格的全部配置现在可在 **/def/vehicle/interior_glass_config.sii** 中访问。

此外，随着刮雨算法的改进，还引入了三个新属性：

- [float] **no_rain_ageing_factor** - 在降雨强度低或无雨时水滴老化程度的调节系数。该值在 <0,1> 范围内越低，在无雨或降雨强度低时水滴干燥所需的时间就越长。
- [float] **drops_wiping_factor** - <0,1> 范围内的系数，定义水滴被推动与被刮除之间的比例，其中 0 表示所有水滴都会被推动，1 表示与雨刮接触时所有水滴都会被清除。
- [float] **drops_moving_offset** - 以米为单位的偏移量，水滴沿雨刮移动方向偏移该距离。

### 交通挂车数据

为交通挂车使用公司涂装的方式已简化。不再需要为每个涂装创建单独的挂车数据变体。新增了**公司涂装自动选择**功能，它会在对应挂车底盘定义位置（即玩家挂车涂装）下的 **company_paint_job** 目录中随机选择一个涂装。可以通过交通挂车定义中的以下属性启用此功能：

```
company_paint_job: true
```

### 模组本地化支持

从 1.33 起，模组可以添加新的本地化字符串。为此，你需要在 **/locale/$language$/** 目录中创建本地化模块。模块文件的名称应为 **local_module.$mod_name$.sii**，例如 **local_module.mod_awesome_jobs.sii**。该文件必须定义单个 **localization_db** 类的单元。

> **注意：** $language$ 应为该本地化所对应语言的标签，例如：英式英语为 **en_gb**，美式英语为 **en_us**，波兰语为 **pl_pl**，捷克语为 **cs_cz** 等。

示例：

```
SiiNunit
{
localization_db : .localization
{
        key[]: "chassis" # This is localization token, you can use it by typing @@chassis@@. We recommend to keep them written using lower-case alpha-numeric ASCII characters.
        val[]: "Chassis" # This is its value in the language. For every language this value can be different.

        key[]: "truck_cabin" # Another localization token.
        val[]: "Cabin" # And its value - as you can notice its always pair of key and val attributes.

        # ...
}
}
```

如果你这样做了，你的模组现在应该已经正确本地化了。

> **注意：** 模组本地化无法覆盖已定义的字符串。也就是说，例如游戏主本地化中已定义的 'chassis' 键的本地化字符串会优先使用；如果未定义，则使用优先级最高的模组。

> **提示：** 我们的系统不会把未翻译的 token 回退为英语，因此你必须为游戏支持的所有语言定义本地化。目前游戏支持以下语言列表。
>
> ```
> bg_bg, ca_es, cs_cz, da_dk, de_de, el_gr, en_gb, en_us, es_es, es_la, et_ee, eu_es, fi_fi, fr_fr, gl_es, hr_hr, hu_hu, it_it, ja_jp, ka_ge, ko_kr, lt_lt, lv_lv, mk_mk, nl_nl, no_no, pl_pl, pl_si, pt_br, pt_pt, ro_ro, ru_ru, sk_sk, sl_sl, sr_sp, sr_sr, sv_se, tr_tr, uk_uk, vi_vn, zh_cn, zh_tw
> ```
>
> 如果你无法承担将模组翻译成每种语言的工作量，我们建议至少把英语本地化复制到其余语言中。
