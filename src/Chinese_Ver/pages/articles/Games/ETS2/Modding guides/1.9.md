# 游戏/ETS2/模组指南/1.9

## 建议

在向支持多文件方式的文件（例如 road_look.sii）中添加新对象时，**强烈建议**在名称中使用后缀或前缀，以避免与我们在补丁中新增的对象发生冲突。否则当新补丁发布时，你可能需要使用批量重命名功能（参见批量重命名）来修复冲突。

部分使用 "sc" 后缀或前缀的新模型仍在开发中，很可能在后续某个补丁中发生显著变化。因此，建议此时避免在模组中使用它们。

## 如何转换地图

- 如果有任何对象使用与类型不匹配的前缀（例如标志的前缀不是 "sign.<name>"），请修复它们。游戏假定该前缀是固定的（参见单元名称检查）。</name>
- 如果你修改了标志，请设置 **distance_type** 属性并删除已过时的属性（参见标志中的变更）
- 如果你修改了道路外观，请更新 ai_speed_type 和 lane_count_* 属性并删除已过时的属性（参见道路外观中的变更）
- 如果你修改了道路材质，请将其转换为新格式（参见道路材质中的变更）
- 如果你修改了地形材质，请将其转换为新格式（参见地形材质中的变更）
- 如果你添加了任何自定义字体，需要更新格式（参见字体中的变更）
- 在编辑器中加载地图。如果加载失败，请检查日志并修复错误。如果你有许多旧的预制件，**-unlimitedlog** 命令行参数在此期间可能很有用。
- 使用编辑器中的查找工具定位报告为 "Bad road item (X)" 的道路项。最可能的情况是，你在这里将英国道路与非英国道路连接在了一起。
- 使用编辑器中的查找工具定位日志中报告为 "<error> Incorrect origin node detected, but not corrected!" 的预制件（在编辑器将地图转换为新格式时），并在必要时重新创建它们。</error>
- 确保日志中不包含与缺失标志相关的任何错误。（参见 #Unit name checks">单元名称检查）
- 如果你添加了新的道路材质或地形材质以用于新的扇区，你可能需要重命名它们，在名称中添加前缀或后缀，以避免与我们添加的材质发生冲突（参见批量重命名）。
- 使用替换对话框（F3，“预制件节点校正”）把我们添加到预制件中的节点添加到地图节点上（参见预制件变更）。
- 保存并重新加载地图，或执行重建（F8）

## 变更

### 涂装变更

卡车现在拥有一个额外的第三套 uv 坐标，其布局有所改进，部分涂装也已更新以利用这一点。涂装可通过涂装定义中新的 **alternate_uvset** 参数选择使用该 uv 坐标。请注意，如果涂装需要模型并不具备的坐标，就会出错，且产生的行为未定义。如果你修改了一辆标准卡车，而玩家使用了我们已更新的涂装之一，这种情况就可能发生。此时你可能需要在模组中包含旧版本的涂装定义与纹理。

### 字体变更

字体文件现在包含底层纹理尺寸的信息。你需要更新所有图像定义行，使其包含尺寸。

例如：

```
image:/font/big_0.mat
```

如果与 /font/big_0.mat 关联的纹理尺寸为 256x512，则新行应如下。

```
image:/font/big_0.mat, 256, 512
```

### 单元名称检查

世界定义文件中的许多内容（例如 /world/sign.sii）期望完整单元名称以固定的前缀组成部分开头（例如 "sign."），其后紧跟一个包含名称的组成部分（有少数例外。如有疑问，请查看游戏自带的原始文件所使用的命名）。视具体情况而定，游戏有时可能仅使用名称组成部分来定位单元，有时则可能用固定前缀与名称构造完整名称，并使用该完整名称来定位单元。为确保游戏通过这两种方式都能找到单元，单元必须采用预期的命名规范。

例如，标志单元的名称预期以 "sign." 开头，因此 "fkmm070" 或 "add.navsg001" 是**不**有效的名称，在地图转换期间将无法被找到。

游戏现在会检查部分单元定义文件中的名称，如果名称不符合预期规范，就会输出错误。

### 渡轮变更

渡轮定义格式已增强，支持向现有渡轮添加新连接，而无需覆盖基础 .sii 文件。

除了 **/def/ferry/&lt;name&gt;.sii** 文件中的标准定义之外，游戏还会加载 **/def/ferry/connection** 中的所有文件。这些文件中的每一个都应包含单个 **ferry_connection** 单元（参见下方示例），它定义两个渡轮之间的连接，且必须命名为 **conn.&lt;from&gt;.&lt;to&gt;**，其中 **from** 和 **to** 是相应渡轮的名称。游戏会将指定的连接添加到基础渡轮定义中；如果该连接已存在，则会覆盖其参数。目前无法通过此机制移除现有连接。

如果多个文件定义了同一连接，则无法确定哪一个生效。因此，即使游戏目前不强制要求，文件也应命名为 **&lt;from&gt;_&lt;to&gt;.sii**（例如 europoort_harwich.sii）。

使用存储在 **/def/ferry/connection/europoort_harwich.sii** 中的连接单元定义从 eurpoort 到 harwich 的连接的示例

```
SiiNunit
{
ferry_connection: conn.europoort.harwich
{
   price: 960
   time: 480
   distance: 207
}
}
```

### 城市定义变更

新增了与交通相关的属性：

- **traffic_density_coef <br>**
  - 修改玩家周围的交通生成密度（默认值为 2.0）
  - 如果多个城市距离足够近，它们的密度系数会相加
- **traffic_density_range**
  - 默认值为 2000.0
  - 设置仍会应用 traffic_density_coef 的最大范围（*超出城市边界*）
  - 所应用的 traffic_density_coef 值随距离递减：在边界处为最大值，在 traffic_density_range 处为 0.0

### 道路外观变更

道路现在支持在左右两部分指定不同的车道数。它们通过新的 **lane_count_left** 和 **lane_count_right** 属性定义。**ai_lane_count** 和 **one_way** 属性现已过时。为了与现有定义保持向后兼容，如果定义中设置了 **ai_lane_count** 或 **one_way** 属性，游戏将覆盖新属性的值。请注意，此回退机制可能在后续某个补丁中被禁用，因此强烈建议更新外观以使用新机制。该功能仅控制道路上的 AI 行为，对道路的可视化没有影响。对更多自定义道路可视化定义（包括更多车道）的支持计划在后续某个补丁中提供。

**ai_road_offset** 和 **actor_lane_count** 属性已过时并被忽略。

**ai_speed_type** 属性现在是枚举，具有以下值：none (-1)、city (0)、regular (1)、highway (2)。目前直接使用数值仍然有效，且与之前的状态兼容，但更推荐使用名称。

### 道路材质变更

为了允许独立添加道路和人行道材质，我们将它们提取到了单独的文件（**road_material.sii** 和 **road_sidewalk.sii**）中，这些文件支持 **.&lt;idofyourmod&gt;.sii** 约定以及带后缀/前缀的单元名称。**road.sii** 内相应数组的值将被忽略。

从旧格式转换地图时，材质索引会被转换为带有相同值后缀的单元（即索引 5 映射到单元 road_mat.5）。如果你添加的材质与此补丁中我们添加的材质冲突，你可能需要使用重命名功能，将新材质移动到新的带后缀表示中。

### 地形材质变更

与道路材质一样，**terrain_material.sii** 也做了修改以允许独立添加。支持 **.&lt;idofyourmod&gt;.sii** 约定以及带后缀/前缀的单元名称。

从旧格式转换地图时，材质索引会被转换为带有相同值后缀的单元（即索引 5 映射到单元 terrain_mat.5）。如果你添加的材质与此补丁中我们添加的材质冲突，你可能需要使用重命名功能，将新材质移动到新的带后缀表示中。

### 信号机变更

游戏现在支持从预制件引用的信号机配置。

信号机的特性定义在 **semaphore_profile.sii** 中。在定位要使用的配置时，游戏会定位名为 **tr_sem_prof.<profile_name>.<country_code>** 的单元，如果失败，则会尝试查找 **tr_sem_prof.<profile_name>**

信号机可视化模型定义在 **semaphore_model.sii** 中。在定位要使用的模型时，游戏会定位名为 **tr_sem_mdl.<profile_name>.<country_code>** 的单元，如果失败，则会尝试查找 **tr_sem_mdl.<profile_name>**

#### 信号机配置

大多数配置属性都是数组。应用配置时，会以信号机 ID 作为索引。预制件信号机的 'type' 必须设置为 '(use profile)'。

如果某个 ID 没有对应值，则使用相应数组属性中的最后一个值

- **model** - token 数组（来自 *semaphore_model.sii* 的信号机模型名称的后缀，不含国家后缀）
- **type**- 枚举值数组：
  - **barrier_distance -**当物体接近时激活的道闸（道路交叉口）
  - **barrier_manual -**在条件满足前保持关闭的道闸（收费站、加油站）
  - **model_only -**若设置，当前实例仅为真实交通信号机的视觉表示
  - **traffic_light -**标准交通信号灯
  - **traffic_light_blockable -**由通行车辆阻挡的交通信号灯（用于控制单向路段，例如道路施工）
  - **traffic_light_major -**带有 'major road' 标志的标准交通信号灯
  - **traffic_light_minor -**带有 'minor road' 标志的标准交通信号灯
- **interval**- float4 值数组（绿、黄、红、黄）
- **cycle**- float 值数组（信号机周期偏移）
- **id_map** - 索引数组
  - 在某些情况下（例如用于道路交叉口的 *model_only* 类型），多个信号机需要链接到另一个信号机，以确保它们同步
- **inherited** - 回退配置的完整名称（当前配置中未设置的属性取自继承的配置）

### 建筑模型变更

building_model 单元的新属性 **min_scale** 和 **max_scale** 可用于随机化模型的缩放。**model_size_override** 属性现已过时，不应在新定义中使用。

新属性 **rand_rot** 指定模型沿垂直轴随机旋转的最大角度范围。模型将相对其默认朝向随机旋转 **<-rand_rot/2;rand_rot/2>** 范围内的值（即指定 360 度将得到完全随机的旋转）。为避免现有地图上出现视觉错误，请勿为已在地图中使用的模型将该属性设置为非零值。

### AI 变更

AI 现在会利用标志中定义的附加信息（见下文）来控制自身行为（例如速度），因此使用正确的标志很重要。

/dev/world/sign.sii 中定义的 sign_models 现在有一个新的可选属性 **traffic_rule**，它引用 traffic_rules.sii 中定义的规则，为该标志指定附加的交通相关语义（例如限速）。

新增了额外的配置文件（/def/traffic_data.sii），用于控制 AI 的行为。其中有许多控制 AI 车辆行为的属性。然而，由于其中一些属性可能在不久的将来发生变化或被移除，**只有配置文件中已有的属性才得到官方支持**。不久的将来还会在该文件中出现更多属性。

当前支持的交通属性：

- *max_vehicle_count* - 所有活动车辆的最大数量。增大该值可能降低性能
- *max_truck_count* - 所有活动卡车的最大数量。增大该值可能降低性能
- *ai_safety_modifier* - 修改 AI 行为的总体安全性。可能值的区间：<-1.0; 1.0>，其中 *-1.0* 表示“最低安全性”，*1.0* 表示“最高安全性”，*0.0* 表示“无变化”

AI 车辆的最大速度现在通过 traffic_vehicle 单元的新属性 **max_speed** 指定，单位为 km/h。属性 **speed** 现已过时并被忽略。

车辆类型现在通过基于枚举的属性 **type** 指定，其值可以是以下之一：**car**、**truck**、**bus**。**speed_class** 和 **use_truck_path** 属性现已过时并被忽略。

车辆的换挡行为现在通过 **gearbox** 属性描述。它允许为不同车速定义不同的加速度：（车速 [km/h]，加速度 [m/s/s]）。

默认值：

gearbox[]: (70, 1.8)

# truck default gearbox

##### 交叉口

**交叉口：**

- **交叉口类型：**
  - **起点交叉口** - 两条或多条曲线从同一定位点引出的点
    - 自动生成 - 无优先权管理
  - **十字交叉口** - 两条或多条曲线相交的点
    - 必须为每条相交曲线设置非零的优先权修正值
  - **终点交叉口** - 两条或多条曲线引至同一定位点的点
    - 必须为每条相交曲线设置非零的优先权修正值
    - 一种特殊情况是**车道汇入**：
      - 所有曲线具有相同的优先权
      - 此时车辆将使用“拉链式汇入”

#### 重要说明

- **必须为参与交叉口的每条曲线生成交叉口结构**
- **结构的存储方式必须使第一个结构包含同级项数量（参与的曲线数）**
  - **所有其余同级项必须紧随第一个之后，并且同级项数量必须设置为零**
- **AI 车辆现在也将预制件曲线用于玩家移动预测，这意味着<br>**
  - 确保玩家可以行驶的所有方向都有有效的**曲线**引出/引入（即使 AI 车辆永远不会前往那里）
  - 使用正确的**转向灯标志** - 车辆会“看到”玩家开启了哪个转向灯，并据此预测其路径
  - 确保玩家可以行驶的所有方向都有**预制件节点**（例如码头入口……）
    - 修改预制件后，你可以使用替换对话框（F3）中的“预制件节点校正”命令，让游戏添加缺失的节点。

### 编辑器变更

#### 批量重命名

编辑器现在支持基于配置文件对某些类型的对象进行批量重命名。首先你需要准备描述应应用哪些更改的配置文件（见下文）。之后你需要在编辑器中加载地图，按 **F3** 打开替换对话框，按 **批量替换** 按钮并确认更改。之后应保存并重新加载地图。

该操作要求旧名称与新名称的单元在操作期间同时存在，因此你需要分步执行：首先将新名称的单元添加到定义中，然后执行重命名，之后从定义中移除旧名称的单元。

配置文件必须保存为 **Documents\Euro Truck Simulator 2\replace.sii**。该文件必须包含单个 **editor_search_replace** 类型的单元。该单元包含字符串数组属性 **sectors**，其中必须包含要应用更改的所有扇区的名称。扇区名称对应存储该扇区的文件的基础名称（例如 sec+0001-0001）。该单元还包含定义替换的其他字符串数组属性。替换字符串的格式为 "old_name|new_name"。支持以下数组：

- **ter_material** - 地形材质
- **road_material** - 道路材质
- **sidewalk_material** - 人行道材质
- **bld_scheme** - 建筑方案
- **model** - 模型
- **vegetation** - 植被
- **road_look** - 道路外观
- **ter_profile** - 地形配置
- **railing** - 道路上的护栏
- **sign** - 道路沿线的路灯/路桩

替换文件示例

```
SiiNunit
{
editor_search_replace : .edit_replace
{
   # List of sectors where the search replace should be performed

   sectors[]: "sec-0002-0007"
   sectors[]: "sec-0002-0008"

   # Terrain material replacement  old terrain material unit suffix | new terrain material unit suffix

   ter_material[]: "24|121"
   ter_material[]: "103|129"

   # Building scheme replacement  old scheme unit suffix | new scheme unit suffix

   bld_scheme[]: "22|2sc"

   # Model replacement  old model unit suffix | new model unit suffix

   model[]: "122|1sc"
   model[]: "757|2sc"
   model[]: "56a|3sc"
}
}
```

#### 类别

model_def、sign_model、prefab_model 和 building_scheme 单元的新属性 **category** 指定一个字符串，表示该单元所属的类别。这可用于相应的编辑器对话框，将项目集合筛选为仅显示属于所选类别的项目。

#### 标志变更

标志现在在编辑器中作为独立项目出现。如果你修改过 editor_data.sii，则需要更新 sub_mode_types 数组，以使相应条目在 UI 中可见。

标志定义中新增了 **distance_type** 属性（0 - 短，1 - 近，2 - 中，3 - 远）。**short_distance** 属性现已过时并被忽略。

标志属性中新增了 **Follow road dir** 复选框。它会根据附近道路对齐标志的朝向，并在道路移动时保持相对位置。
