# 游戏/ETS2/模组指南/1.35

## 简介

本页面包含针对游戏新更新的模组制作指南。

为了更好地理解单元的变化，建议查阅 [单元文档](../../../Documentation/Engine/Units.md) 页面。

## 建议

- 当你以原始模型为基础制作自己的模型时，也请在模组中加入该模型所使用的**所有**原始 /automat/ 文件。这些文件的名称是根据其内容生成的 CityHash64 哈希值，因此每当我们以任何方式更改材质参数时，都会改用另一个文件来存储它们，而如果没有其他模型使用原始参数，原始文件可能就会不复存在。
- 修改原始模型时，请务必包含该模型的**所有**组件（pmg+pmd），而不仅仅是你修改过的组件。否则一旦我们更改了模型，就有崩溃的风险。
- 一如既往，在向支持多文件方式的文件（例如 road_look.sii）中添加新对象时，**强烈建议**在名称中使用后缀或前缀，以避免与我们在补丁中新增的对象发生冲突。否则当新补丁出现时，你可能需要使用批量重命名功能（参见批量重命名）来解决冲突。

## 如何转换地图

- 加载地图
- 执行重建（F8）
- 保存地图
- 对于外观选择已发生变化的模型，选择正确的外观
- 如果保存时生成了类似 "Sign template item 123 does not exist in template 'ABC'" 的错误消息
  - 在内容浏览器中找到该模板
  - 右键单击它并选择 "Edit"
  - 在 "Sign Editor" 对话框中选择 File > Clean up overrides

## 更改与新增功能

### 曲线项

#### 曲线模型定义

**curve_model.sii** 文件中的每一条定义都必须采用以下格式：

```
       ----------  Internal Data Type
      |
      |          ------  Data Type Identification
      |         |
      |         |    ----- User Name
      |         |   |
      v         v   v
curve_model : curve.2 {
     category: "Walls"                                          # Category
     name: "Warehouse wall"                                     # Curve model name
     model_desc: "/model/warehouse/tiled_wall.pmd"              # Model Path
     dynamic_lod_desc[]: "/model/warehouse/tiled_wall_lod1.pmd" # LOD1 Model Path
     dynamic_lod_dist[]: 50                                     # LOD1 switch distance in meters
     dynamic_lod_desc[]: "/model/warehouse/tiled_wall_lod2.pmd" # LOD2 Model Path
     dynamic_lod_dist[]: 100                                    # LOD2 switch distance in meters

     variation[]: "var_name1 | center1:2 | center2:5"           # Part variation definition
     variation[]: "var_name2 | center1, center2:5"
     start_part[]: "strt1|strt1a"                               # Start parts list per variation
     start_part[]: "strt2|strt2b"
     end_part[]: "end1"                                         # End parts list per variation
     end_part[]: "end2|end3|end4"
     smooth_surface: false                                      # Smooth surface
     color_variant[]: "red: 255, 0, 0"                          # Color variants
     color_variant[]: "blue: 0, 0, 255"
     vegetation[]: "tree_a : vegetmodel.cityalley.smalltree02a | 5:8 | -2:2 | 0.5:1.5 | 0:360"
     vegetation[]: "tree_b : vegetmodel.cityalley.smalltree02b | 5:8 | -2:2 | 0.5:1.5 | 0:360"

     fixed_step: 20                                             # Use given fixed step between parts
     fixed_inner_start[]: strt1                                 # Use given start part for "inner" curve (definition per variation)
     fixed_inner_start[]: strt2

     fixed_inner_end[]: end1                                    # Use given end part for "inner" curve (definition per variation)
     fixed_inner_end[]: end2
}
```

- **Internal Data Type, Data Type Identification** - 必须保持原样，且为必需项。
- **User Name** - 在游戏中必须对每一段栏杆都唯一（即使是跨所有 dlc、模组等也是如此）。该名称是一个 token，最多可包含 12 个字符，取自以下字符集：_0123456789abcdefghijklmnopqrstuvwxyz。最佳实践是在名称中添加能够标识该 dlc 或模组的后缀，以避免名称冲突。
- **Category** - 用于在建筑项属性对话框中简化导航的分类名称。字符串值。
- **Name** - 建筑方案名称。字符串值。
- **Model Path** - 模型文件（*.pmd）的路径。
- 动态 LOD 的最大数量为 3
- **LOD Model Path** - 用于低多边形 LOD 的模型文件（*.pmd）的路径。
- **Variation** - 中间部分变体定义
  - <br><code>Variation name (token) | part_name [,part_name ...] : weight [ | part_name [,part_name ...] : weight]</code>
- **Start part** - 所有可用作起始部分的有效部分的数组
- **End part** - 所有可用作结束部分的有效部分的数组
- **Smooth surface** - 对几何法线执行平滑插值。默认值：false
- **Color variants** - 用户自定义的顶点颜色乘数，用于建筑项几何体的生成（可选）
- **Vegetation** - 实例化植被的定义采用以下格式：
  - <br><code>Instance name (token) : vegetation model unit name | min_width : max_width | min_offset : max_offset | min_scale : max_scale | min_rot : max_rot</code>

#### 自动电线生成

曲线模型可以包含用于自动生成电线的定位点。这些定位点采用以下命名约定：

定位点名称：**w_X_Y_Z**，其中：

- **w_** - 前缀
- **X** - 电线类型
  - **f** - 不带任何下垂距离的平直电线
  - **t** - LOW 电线下垂，具有平直电线的粗细（细电线）
  - **l** - LOW 电线下垂
  - **m** - MEDIUM 电线下垂
  - **h** - HIGH 电线下垂
- **Y** - 电线线路索引，从 0 开始
- **Z** - 唯一后缀，后缀可以是任意字符

示例：

```
w_h_0_a, w_h_0_b, w_f_1_0
```

### Mover/walker 的统一与改进

mover 及类似对象的处理方式已完全重做。**walker 项**现已过时，并且将来可能会被移除。如需类似功能，请使用带有 [Mover 模型组](../../../Documentation/Engine/Mover%20model%20group.md) 的 **mover 项**。mover 项现在支持 walker 项中的所有重要属性。

此外，`mover_model_u` 属性 `model_anim_alt` 现在也已过时，并且**将在下一次更新中被移除**。这意味着使用该属性的**行人挂接**将无法正常工作。推荐的做法是将它们替换为使用 [Mover 模型组](../../../Documentation/Engine/Mover%20model%20group.md) 模型的新 mover 挂接。

### 语音导航

语音导航功能的数据格式在 [Documentation/Engine/Units/sound_data_voice_navigation](../../../Documentation/Engine/Units/sound%20data%20voice%20navigation.md) 中有所描述。

### 动态 LOD

现在使用 LOD 数组（数组 **dynamic_lod_desc[]** 和 **dynamic_lod_dist[]**）取代了单一的静态 LOD（属性 **lod_desc** 和 **lod_dist**）。逻辑相同：*descriptor* 定义 LOD 模型的路径，*dist* 定义从多远处开始使用它。目前旧式 LOD 定义仍会被加载并转换，但这一支持最终可能会在未来的更新中被移除。

受影响的单元有 **prefab_model**、**model_def** 和 **curve_model**。此外，**sign_model** 新增了 LOD 数组。

### 时区子区域

时区子区域的数据已在 1.34 更新中悄然引入（在 ATS 中可查看俄勒冈州的 Malheur 县，在 ETS 中可查看俄罗斯的加里宁格勒地区）。

一组数据位于 **city_data** 单元中，用于基于城市的静态时区用途（例如游戏经济中的交付时间）：

- **time_zone**（整数，默认值为未定义值，以一周的分钟数 10080 表示）- 给定城市的时区，以分钟为单位
- **time_zone_name**（字符串，默认为空）- 最终时区的名称

如果城市时区未定义（或为 10080），则使用该城市所属国家的时区。

第二组附加数据由存储在 **country_data** 单元中的三个同步数组（预期长度相同）组成，用于在地图上进行时区的空间检测：

- **secondary_time_zone_area**（float4 数组）- 编辑器坐标中矩形区域的元素
- **secondary_time_zone**（整数数组）- 给定区域的时间差，以分钟为单位
- **secondary_time_zone_name**（字符串数组）- 给定区域的时区名称

如果某个点位于给定国家内（由地图逻辑根据道路/预制件和边界判定），则会检查所有现有的矩形元素，看其是否具有与该国家不同的时区。第一个匹配的区域元素即定义正确的时区。如果找不到任何区域，则改用国家时区。

### 经济数据

**economy_data** 单元中处理紧急加油的新属性：

- **refuel_fuel** - 单次紧急加油所提供的燃油量（默认 50.0，单位为升），如果驾驶员拥有的燃油更多，则该服务被禁用
- **refuel_price_base** - 该服务的基础固定价格（默认 150.0）
- **refuel_price_factor** - 相对于给定国家常规柴油价格的基础燃油成本乘数（默认 3.0）
- **refuel_time_base** - 紧急加油延迟的基础时间（默认 1800.0，单位为秒）

### 交通数据

#### 停放的车辆/挂车

停放车辆/挂车的属性 **allowed_trailer** 现在也会被解释为挂车链定义。

> **注意：** 属性 **allowed_trailer_count** 现已过时，因为挂车数量会根据挂车链自动确定。

#### 生成密度规则

挂车链支持也已添加到*生成密度*交通规则（*traffic_rules_spawn.sui*）中。**str_params** 属性中除第一项之外的所有项现在都会被解释为允许的挂车链。这对于在地图中指定生成自定义挂车（自定义货物）的区域很有用。

示例：

```
traffic_rule_data : traffic_rule.s_train_c2
{
	name: "Spawn density - cargo train (plane)"

	rule: "density"

	str_params[]: "train_cargo"
	str_params[]: "train_car.trplane_car 1 | train_car.trplane_care 1 | train_car.trplane_car 1 | train_car.trplane_care 1 | train_car.trplane_car 1 | train_car.trplane_care 1"

	num_params[]: 0.0	# 00:00
	num_params[]: 0.015	# frequency
	num_params[]: 1		# count limit
}
```

#### 挂车链

支持的挂车现在只需在一处定义：*在 **traffic_vehicle** 中通过定义整个挂车链*（此前是由按车辆/挂车类型 + 按车辆/挂车的组合构成）。**traffic_trailer**、**traffic_vehicle_type** 和 **traffic_trailer_type** 中的相关属性现已过时。提供了部分向后兼容性（使用旧属性可能无法正确创建更复杂的挂车配置）

> **注意：** 为了避免不必要的复杂性，已移除对通配符的支持。

> **提示：** 如果你使用过（现已过时的）属性 **allowed_tractor**，可以通过为使用过该属性的挂车设置 **spawn_ratio: 0.0** 来实现类似的功能。这样，除非在 **trailer_chains** 中显式设置，否则它们不会被任何车辆选中。

挂车链的每个元素既可以通过挂车类型名称指定（将生成该类型的随机挂车模型），也可以直接通过交通挂车单元名称指定。可选地，可以为每个元素指定出现次数的最小值和最大值。元素与次数之间用 “|” 分隔。

**示例：**

`trailer_chains[]: "semi_trailer"` - 该车辆将拥有一个类型为 **semi_trailer** 的挂车

`trailer_chains[]: "traffic_trailer.first | traffic_trailer.middle 2-4 | traffic_trailer.last"` - 包含特定元素的挂车链，'traffic_trailer.middle' 可出现 2-4 次。

#### 挂车类型与存储重命名

一些挂车类型及相应的存储已被重命名，改用更通用的 *special* 后缀，以更好地符合它们的用途。它们包含的挂车始终是被显式选中的，而不会在整个存储中随机选取：

- *traffic_storage_train_car_pass.sii* → *traffic_storage_train_car_special.sii*
- *traffic_storage_trailer_parked.sii* → *traffic_storage_trailer_special.sii*

### 车辆数据

#### 驾驶室悬架

驾驶室现在像真实卡车那样通过 4 个弹簧连接到底盘（此前仅使用一个弹簧来模拟驾驶室的行为）。当 g_colbox 激活时，可以看到弹簧位置以黄色十字显示。

`physics.sii` 中的数据成员 **cabin_pitch_force_scaling_factor**、**cabin_pitch_damping_factor**、**cabin_roll_force_scaling_factor** 和 **cabin_roll_damping_factor** 现已过时。

`physics.sii` 中新增了以下数据成员：

- **cabin_suspension_travel**（浮点数，默认 0.05，单位为米）- 指定驾驶室弹簧在承受驾驶室重量且处于静止位置时的长度
- **cabin_suspension_damping_factor**（浮点数，默认 1.0）- 驾驶室悬架减震器的相对强度乘数
- **cabin_sway_bar_factor**（浮点数，默认 1.0）- 驾驶室悬架横向稳定杆（用于抵抗驾驶室的相对侧倾）的相对强度乘数
- **cabin_cog_height_offset**（浮点数，默认 0.5，单位为米）- 指定驾驶室定位点与驾驶室重心（COG）之间的高度差（重心高于定位点）

> **注意：** 此外，驾驶室悬架的工作点可以通过 cvar g_cabin_suspension_stiffness 更改。其默认值（1.0）对应工作点 0.65（当我们把驾驶室重量压上去时，弹簧压缩到其长度的 65%）。该 cvar 的值越低，工作点越低，弹簧也就越软（g_cabin_suspension_stiffness 0.0 会将工作点设为 0.5）。

#### 货物模型随机化

如果为给定挂车声明了不止一个货物可视化模型（参见 **cargo_model_match** 单元中的 **data_path** 数组，该单元存储在自有挂车货物的 **def/cargo/*/** 文件夹中），则使用的模型会从中伪随机地选取。

#### 底盘配件中的重心数据

重心（COG）数据已从挂车定义移至 [accessory_chassis_data](../../../Documentation/Engine/Units/accessory%20chassis%20data.md)。它们更易于编辑，数量比挂车定义更少，而且在给定底盘上货物的装载方式通常是相同的。

取值逻辑本身与之前相同：**cog_cargo_mass_min**（浮点数，默认 0）和 **cog_cargo_mass_max**（浮点数，默认 20000）设定边界限制，**cog_cargo_offset_min**（float3，默认 (0,0,0)）和 **cog_cargo_offset_max**（float3，默认 (0,1,0)）设置用于插值的数值。

此外，默认重心现在位于模型的中心，这是基于对挂车几何体的某种分析得出的，与挂车模型的场景原点无关。因此，作为变通手段使用的纵向偏移应予丢弃。

#### 挂车底盘调整数据

单元 **trailer_configuration**（文件夹 **def/trailer_owned/*/configurations/**）中新增了 token **equivalency**（默认为空）。每个非空值都定义了一组封闭的配置。任何其他具有相同 **equivalency** token 值的配置都被视为同一（些）挂车的不同变体。按逻辑来说，它们应具有相同的成本和等级（但游戏既不会交叉校验也不会强制要求），并且通过挂车调整器进行的任何此类切换都是免费的。

#### 模组卡车的经销商 UI

允许所有模组卡车品牌在同一个特定的 UI 界面上可用。当你在 Mod Manager 中激活一个包含已定义卡车品牌的模组后，即可使用此功能。当检测到这样的模组时，卡车经销商世界地图上会出现一个按钮，引导你进入该界面。

要在你的模组中添加新品牌，只需在 **/def/vehicle/truck_dealer** 中创建一个以你的品牌命名的目录。在该目录中放入你的库存卡车报价 .sii 文件。例如，对于名为 **X Brand** 的品牌，在上述路径下创建一个名为 "**xbrand**" 的目录。接下来需要用有效的卡车报价填充该目录，也就是包含车辆及其配件的 .sii 文件。这些配件与车辆配置的定义存储在 **/def/vehicle/truck** 路径下的目录中。有关该文件夹结构与内容的更多信息，请参阅专门的页面：[玩家卡车定义](../../../Documentation/Engine/Game%20data/Player%20trucks%20definitions.md)。

需要说明的是，如果你要创建新的卡车定义，单元 [accessory_truck_data](../../../Documentation/Engine/Units/accessory%20truck%20data.md) 应使用以下约定命名：`vehicle.<brand>.<series>`。因此沿用上面的例子，如果 **X Brand** 的报价使用新的卡车定义，则 `data.sii` 中 accessory_truck_data 的名称应如下所示：`accessory_truck_data : vehicle.xbrand.t_9000`

> **注意：** 目前，该功能不支持仅在 **/def/vehicle/truck_dealer_uk** 中定义的英国专属卡车品牌。

此外，你可以在 **/material/ui/brand_logo** 目录中为你自己的品牌经销商添加品牌徽标。为此，请以新品牌的名称（此处即 "**xbrand**"）创建一个 .mat、一个 .tobj 和一个 .tga 徽标文件。使用所提供的 [转换工具](../../../Documentation/Tools/Conversion%20Tools.md#Download_.26_Installation) 转换这些文件，并将生成的转换结果添加到上述目录中。徽标尺寸必须为 **128x64**。如果未设置品牌徽标，则该位置将显示一个空的材质图像。

最后，你仍然可以使用相同的方式将模组卡车添加到游戏内的经销商：在 **/def/vehicle/truck_dealer** 路径下创建一个以该游戏内品牌名称命名的目录，并向其中填充新的报价。因此，例如如果模组作者想为 DAF 添加新报价，就需要在其模组的 truck_dealer 路径下创建一个名为 "**daf**" 的目录，并在其中添加卡车报价。添加到游戏内品牌的所有模组内容都会同时出现在模组品牌经销商和实际品牌经销商中。

#### 挂车支撑声音

默认值现在设为空。因此只有在数据中显式声明时才会有声音。

#### 变速箱模式名称

单元 **accessory_transmission_data** 新增了两个字符串属性 - **auto_mode_name**（默认 "A"）和 **manual_mode_name**（默认 "M"）。如果卡车显示屏包含变速箱模式元素（id 1310），则它们的值会在仪表盘计算机显示屏中用作该元素。

#### 车轮碰撞偏移改进

此前，车轮碰撞的表示使用硬编码的偏移和宽度，因此并不总能与视觉表现精确匹配。现在大多数车轮的碰撞默认就应能正确匹配。

唯一需要特殊处理的车轮是那些轮胎“中部”相对于零点存在非零偏移的车轮（这可能由多种原因造成，例如为了让烘焙过的（而非轮胎 + 轮辋）车轮按预期旋转，或为了让多种宽度的轮胎与同一种轮辋/轮毂配件兼容）。

对于此类车轮，`accessory_wheel_data` 中有一个名为 **wheel_shift** 的新参数。为了使碰撞正确生成，该偏移量应等于场景零点与轮胎零点之间的差值。

> **注意：** 要让碰撞按预期工作，还需要的另一项条件是确保 BB 定位点位于轮胎的外缘。

#### 雨刷持续时间与延迟格式

在单元 [**accessory_interior_data**](../../../Documentation/Engine/Units/accessory%20interior%20data.md) 中，属性 **wiper_delay** 已被移除。取而代之的是新增的属性 **wiper_duration_and_delay**（float2 数组）。每个元素包含一个激活状态的动画长度（以秒为单位）以及动画循环之间的时间延迟（以秒为单位）。

如果未正确声明 **wiper_duration_and_delay**，则默认为单个元素 float2(2.0, 0.0)，在这种情况下它作为唯一的激活状态。
